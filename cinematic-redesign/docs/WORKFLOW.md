# 시상식 영상 제작 워크플로

행사명과 시상 순서, 수상자 표기, 유효 화면, 상영 큐와 소스 사용 권리를 먼저 확인한다. 확정 정보와 시안 가정은 산출물에 구분해 적는다. 본편의 첫 결과는 승인 대기 중인 글자를 명시한 12초 오프닝 애니매틱과 수상자 공개 시안이다.

| 역할 | 입력 | 제출할 산출물 |
| --- | --- | --- |
| Research Director | 목적, 관객, 현장 조건, 독립 자료 | 출처별 발행자·날짜·타임코드·권리, 채택할 표현 원리와 한계 ([리서치](research/production-research.md)) |
| Creative Director | 리서치와 공인 행사 정보 | 콘셉트 2안, 장면별 목적·문구·홀드·큐, 선택 근거 ([스토리보드](storyboard/README.md)) |
| Art Director | 콘셉트, 로고, 가장 긴 이름 | 축소 상태에서 비교할 스타일 프레임, 팔레트·타이포·안전 영역·자산 출처 ([디자인](design/README.md)) |
| Motion Director | 스토리보드와 스타일 프레임 | 프레임 번호, 타이틀 진입·정착, 장면 연결 방식, 타이밍을 재현할 애니매틱 |
| Technical Director | 승인 문안과 애니매틱 | 프레임 결정적 Remotion 구현, 환경·렌더 스펙 및 재현 명령 |
| QA Director | 요구사항, 산출물, 테스트 파일 | 첫 평가, 결함·담당자, 수정 후 동일 기준 재평가, 통과·실패·보류 근거 ([검토표](reviews/README.md)) |

리서치, 콘셉트, 디자인, 모션 설계, 런타임 점검은 독립 하위 에이전트로 병렬로 시작할 수 있다. 합의된 산출물 경로와 바뀐 전제는 전달하고 같은 파일을 동시에 편집하지 않는다. QA 검토자는 평가할 산출물과 요구사항을 받는다. 필요하면 새 컨텍스트로 검토를 시작한다. 하위 에이전트를 사용할 수 없으면 위 순서로 역할을 바꾸고, 제작과 평가를 별도 패스로 수행한 사실을 기록한다.

## 방법론을 프로젝트 절차로 적용

- **Deep Research**. 검증할 질문을 한 문장으로 쓰고 원문과 독립 자료를 비교한다. 근거가 약한 주장은 가설로 표기한다. 영상에서 채택할 표현 원리와 자산 권리를 각각 기록한다.
- **BMAD Method**. 프로젝트 목표, 수락 기준, 구현 항목을 한 줄씩 연결한다. 예를 들어 “뒷자리에서 수상자명 읽기”는 “승인된 긴 이름과 최대 폭 활용”을 요구하며, 정지 프레임과 실제 상영에서 각각 확인한다. 검토를 통과한 항목만 후속 제작에 넘긴다.
- **Creative Intelligence Suite**. 콘셉트, 색과 타이포, 모션을 바꿔 최소 2안을 비교한다. 두 안에 같은 승인 문구와 화면 비율을 사용한다. 정보 공개 순서, 상영 가독성, 제작 위험을 기록해 선택 근거를 남긴다.
- **Elephant & Goldfish Model**. 제작자는 가정과 의도를 기록한다. 별도 컨텍스트의 검토자는 요구사항, 산출물과 근거 파일로 문제를 재현한다. 초안 제작자에게 위치와 영향을 전달하고 수정 후 다시 평가한다.
- **Holmaark**. 이름으로 동작이나 권한을 추정하지 않는다. 배포 후보가 제공되면 발행자, 공식 URL, 커밋, 라이선스, 실행 코드를 확인하고 채택 여부를 기록한다.

## 승인과 후속 작업

초안 → 독립 평가 → 문제점 기록 → 수정 → 재평가 → 결과 기록을 적용한다. 영상미, 글자 가독성, 기업 행사 적합성, 장면 연결, 기술적 안정성, 최종 상영을 각각 확인한다. 현장 장비가 필요한 판정은 보류로 남기고 재생 규격과 리허설 방법을 기록한다.
